# Start or continue development

1. **Locate.** Read repository instructions, [setup](../../../docs/setup.md) and [profile](../../config/repo-profile.yaml). Preserve the request. Start with the [semantic writer](journal-protocol.md); it supplies configuration and identities.
2. **Read context.** Use the [context helper](../context.md) for the task. Read all context pages: next phase, contract, issues and open operations. Keep its `context_id`; a changed context requires a fresh read.
3. **Act.** Check current permissions. Supply one meaningful step using the [templates](../../templates/development/). Record operation intent before dispatch, then its handle and actual outcome. Retain native output and explain interpretation. Use [recovery](../recovery.md) for uncertainty.
4. **Verify.** Review the phase and specification requirements against evidence. Specification acceptance and final verification are mandatory. Other skips need an explicit user instruction with attributed scope review. Reconcile earlier skips when accepting a specification. Requirements survive every skip.
5. **Continue.** Record evidence-backed results. Changed source invalidates affected proof; failures remain visible. Generate the task report at handoff and link it. A missing helper leaves dependent claims unverified.

Record operations for execution claims or activity needing interruption recovery. Ordinary read-only inspection cites files directly. Harness changes use [maintenance](../maintenance/harness-maintenance.md); tasks keep captured configuration.
