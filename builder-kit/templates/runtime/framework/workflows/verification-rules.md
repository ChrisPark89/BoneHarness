# Verification rules

- Follow the declared phase order. Task initialization combines intake and baseline; Pattern review remains visible.
- Specification acceptance and final specification verification are mandatory. A phase PASS cannot substitute for acceptance.
- Other phases may be USER_SKIPPED with the original user instruction and attributed phase/task scope review. Hashes establish bytes, not authorship. Reconcile every earlier skip when accepting a specification. Accepted requirements are never waived.
- PASS needs relevant evidence. Execution phases need a successful matching operation; review phases need attributed review. Fixture evidence cannot prove real task success. A valid failure cannot become PASS through interpretation.
- Save operation intent before dispatch. Preserve inputs, source/specification, handle and outcome. Resolve every live or uncertain operation before advancing or skipping. Closed operations never change; retries use new IDs and retain failures.
- Evidence must precede the claim that uses it. Changed source invalidates affected proof. Re-evaluate required criteria against the accepted specification and current scoped source at final verification.
- The writer supplies identities and checks sequencing; it does not execute tools or invent judgments. Resolved phases and satisfied required criteria support completion.
- Respect current permissions, preserve captured configuration, and use maintenance for harness changes.
