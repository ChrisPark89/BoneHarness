# Prepare verification

1. Read the accepted specification. For each required criterion, identify suitable evidence: tests, actual program behavior, static checks or attributed inspection.
2. Inspect existing coverage. Identify checks to reuse and missing cases; name expected results, including relevant failure/boundary cases.
3. Record prerequisites: program/build version, environment, data, permissions and tools. Explain unresolved gaps and the action needed before verification.
4. Prepare missing tests, data or review instructions when feasible. If a check must be written later, state when and why. Planning a check never counts as executing it or satisfying a criterion.
5. Record a short criterion-to-check mapping in the phase summary, citing existing tests or documents. Avoid a separate document unless the mapping cannot fit clearly. Submit the phase result; follow any human-review checkpoint before continuing.

The LLM judges relevance and coverage. Scripts validate evidence and approval records; they cannot establish that chosen checks fully test the requirement. Final specification verification still requires actual supporting evidence.
