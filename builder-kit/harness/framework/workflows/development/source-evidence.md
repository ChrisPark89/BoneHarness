# Source and evidence

Preserve referenced originals before updating the human specification view. Acceptance resets affected proof; termination evidence keeps operations closed.

Choose exact source roots and exclusions at initialization when operations are needed before specification. Acceptance fixes the source scope; revisions require new acceptance. Include all inputs relevant to the accepted criteria, including untracked files.

The writer snapshots selected file membership and bytes before source-bound work. Current context includes the live source identity; stale context is refused. Source changes invalidate dependent implementation, preflight, build, testing and final review/verification judgments. Revisit affected prerequisites before dispatching more work.

Evidence references local bytes with explicit provenance: REVIEW, EXECUTION or FIXTURE. Fixtures never support real completion. Execution outcomes need an actual operation, source/specification identity, and terminal evidence. Use [command capture](command-capture.md) for local commands; keep raw output separate from interpretation. Record material targets/environments and asynchronous deadlines/handles.

A phase summary records the LLM's review judgment and may cite existing documents or execution output. No separate review file is required. Required criteria need evidence at final verification.

Reports are derived snapshots. Regenerate after changes. JSON and Markdown carry matching generation identities; interrupted publication can leave a mismatched pair. Local hashes do not prove who authored evidence.
