# Project working guidelines

Only `builder-kit/` is distributed. Read at startup and after condensation; share with delegated agents.

## User experience

- Target: `init` → show gaps → try the harness. Noncritical gaps allow eligible work; connecting every adapter is unnecessary.
- Show affected phases, blockers and next actions. Never silently skip work.
- Make outcomes transparent: what happened, passed, failed, was skipped or remains unknown, with evidence links.
- Keep updates simple; preserve customization/history. Identify unfinished tasks affected by incompatibility.

## Before changing the design

1. Ask who needs each field/file and what mistake it prevents or recovery it enables. Remove unnecessary complexity; clarify consequential ambiguity.
2. Classify information as required, conditional or derivable; trace consumers before removing it.
3. Keep human pages within 200 words: short tables/bullets supporting a decision. Keep CLI use optional for daily work.
4. Give LLMs short sequential guides and an index; parse lengthy structured records.
5. Update affected design/spec/plan together. Separate proposals from verified behavior; check proportionately.

## Preserve

Specification acceptance and final verification are mandatory. Other skips require explicit user instruction; specification requirements survive.

Retain failures and recovery evidence. Task initialization replaces NEW/BASELINE; Pattern review stays visible. Older histories retain matching tools.
